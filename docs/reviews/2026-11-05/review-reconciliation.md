# Review reconciliation and 3.10.0 implementation

[Codex](https://github.com/murphys-logs/murphys-logs/pull/15#pullrequestreview-5777910770) (with three inline threads) and [Antigravity](https://github.com/murphys-logs/murphys-logs/pull/15#issuecomment-6646067302) (with one inline thread) independently reviewed [Claude's findings](claude-review.md) at PR head **`3d26a11`**. This document records how each point was handled, and what PR #15 now changes in the app (**3.10.0**).

**Firebase boundary.** None of these changes touch Firebase SDK imports or versions, `firebaseConfig`, initialisation, Auth calls (`signInWithEmailAndPassword`, `signOut`, `onAuthStateChanged`), Firestore collections, document schemas, `onSnapshot` registrations, `runTransaction` and `setDoc` calls, or any helper that runs inside a transaction callback (`stoolMerge`, `operationData`, `stoolMovePatches`, `stoolRecoveryPatch`). The new status logic only *reads* `snap.metadata.fromCache`, which the existing listeners already deliver. Outbox key formats and operation shapes are unchanged; a new `murphy-outbox-quarantine:` prefix holds entries the owner sets aside.

## Round two: Codex re-review of `d467da7` (R1–R7)

[Antigravity's re-review](https://github.com/murphys-logs/murphys-logs/pull/15#issuecomment-6646502175) found every item fixed and judged the PR ready for physical-iPhone acceptance. [Codex's re-review](https://github.com/murphys-logs/murphys-logs/pull/15#pullrequestreview-5778189278) confirmed the Firebase boundary and most fixes, and raised R1–R7. All seven are accepted and fixed, still with no Firebase change. Each now has a regression scenario in `tests/offline-friction.browser.cjs`.

| ID | Codex finding | Fix |
|---|---|---|
| R1 (P2) | The global `murphy-window` lock elects one holder; it doesn't prove there are no other windows, so window C took live window B's draft | The global lock is removed. Each window holds `murphy-draft-owner:<its session>` while open. A recovered draft is auto-restored only if this window can take **that session's** lock (so no live window owns it) **and** the stored payload is byte-identical after the wait. Otherwise the Restore entries prompt remains. Corrected claim: WebKit can release a suspended page's locks, so after suspension this falls back to "the draft may be shown in two windows, both still needing Save", never to loss. iOS Home Screen behaviour is checked on a device (row 4 of the checklist) |
| R2 (P2) | Shallow validation: `{items:[null]}` and a `stools` delta without `drop` passed, then threw during replay | `validQueuedOp` now checks nested aggregates, recovery, regime and move fields, plain-operation `patch` and `remove` paths, and stool deltas (`put` ids, `drop` array), plus `days` ids as dates. It checks shape only; AG-05's semantic conflicts are still not decided here |
| R3 (P2) | Quarantine destination dropped the queue prefix, so equal suffixes collided and one payload was lost | The destination is `murphy-outbox-quarantine:<uid>:<encodeURIComponent(full original key)>`; a different envelope already there is never overwritten (a `~n` suffix is added instead). The full `{key,raw}` envelope is verified before each source is removed. A partial failure reports how many were moved and that the rest are still in place |
| R4 (P2) | After the last set-aside, the recovery route disappeared and Full backup omitted quarantine | Sync & storage shows the set-aside count and **Save recovery file** whenever quarantine exists. Recovery files and **Full backup** (`setAsideOutbox`) include every set-aside envelope; set-aside entries are never replayed or sent |
| R5 (P3) | The pinned Undo stayed until some other render | A timer redraws at expiry, and resume (focus or visibility) re-evaluates notices. The durable Undo is untouched |
| R6 (P3) | "Last confirmed" could carry over to another account on a same-page switch; a flush for A finishing after switch to B updated B's status | `subscribe()` clears it; `noteServerConfirmed(uid)` ignores evidence from a previous account's flush or listener; `flushTask` returns early if the active user switched; it reloads from that account's own device key |
| R7 (P3) | The Sync & storage age ignored held entries and always promised automatic sending | The age includes unreadable entries' key timestamps. When sending is held, the text says so and offers the recovery actions instead of "syncs automatically"; Retry is hidden while it can't help |
| R1 / duplicated sessions (Codex verification) | A duplicated tab inherited sessionStorage and activated or overwrote a live tab's draft without checking ownership | Each document now writes to a fresh session key. The inherited session is only a recovery candidate, subject to the owner lock; the failing duplicate-tab regression now preserves both unsaved values |
| R1 / missing ownership evidence (Codex verification) | A live writer whose owner-lock request rejected still wrote a draft that another window automatically moved; legacy writers never held these locks | A local draft records `ownerLock:true` only after its writer holds the lock. Automatic recovery requires that evidence and the candidate's lock; legacy, unverified v2, unavailable and rejected ownership cases retain the explicit Restore prompt and Save |
| R1 / delayed storage failure (Codex verification) | A storage read that failed after the asynchronous lock grant caused an unhandled rejection | The post-wait read now fails safely to the prompt. Browser probes also cover a changed payload, dismissed candidate and account switch during the wait; none consumes the original draft |
| R2 / unsafe operation shapes (Codex verification) | Missing restore patches, malformed numeric/list/timestamp fields and removal paths could still throw or poison later replay; a huge regime count could loop without bound | Local outbox validation now checks the fields dereferenced by replay/sending, safe document IDs and nesting, and emitted removal-path shapes. Multi-marker regime Undo requires its matching retained indices. Valid legacy/guarded operations remain readable; AG-05 semantic move conflicts remain visible |
| R2 / legacy normalization (Codex verification) | Nested legacy stool Undo missed timestamp repair, and an unusable recovery-key clock aborted the queue scan | Timestamp normalization now visits nested aggregates and stays inside each entry's error boundary. Failing-then-passing tests show valid legacy Undo drains, while malformed entries retain their exact bytes and later observations remain visible and exportable |
| R3 / source changed during copy (Codex verification) | A source rewritten during the quarantine copy was removed even though its replacement bytes had not been copied | Recheck the source after verifying the destination, immediately before removal; on mismatch retain both the old copied snapshot and current source. Regression coverage also checks original prefix collisions, repeated set-aside and quota failure on the first or second copy |
| R4 / corrupt quarantine metadata (Codex verification) | An envelope's `storedAt` property could override its actual storage key and crash sorting, Settings and both recovery exports | The actual storage key is authoritative. Corrupt-metadata regression tests now pass, and Full backup round-trip coverage confirms quarantine is included in the file without being replayed or sent on import |

Noted, not changed: the hold compares queue keys lexically, the same order in which they are sent. FR-03's known mixed-width key ordering limitation (13-digit keys sorting before 12-digit ones) therefore still applies; numeric ordering across all historical formats is not claimed.

## Test changes to existing suites

Each change below reflects deliberate new behaviour, not a loosened check:

- `restore-sync.test.cjs`: 10 CC3-02 scenarios end with one listener server-backed and the others cached, so they now expect **"Cached; checking sync"** (CX-01). Two CC4 escaping tests give their Undo a fresh `createdAt` so it is pinned (CR-03).
- `ui-ergonomics.test.cjs`: the Today-banner test now expects the 94-day-old Blood item in Review and not on Today, and adds an in-window control that still alarms (CR-02). Release identifiers move to 3.10.0. A new **AG-13** back-off test brings the Node suite to 180.
- `history-review.browser.cjs`: CC-D1's bounded-banner check moves its latest Blood date inside the vet window, so the compact multi-date banner is still tested (CR-02).
- `settings-exports.browser.cjs`: the old "Sign out must not add a guard" assertion now checks the CR-06 guard. With unsynced changes, one confirmation appears; declining never calls `signOut` and keeps the queue. The no-pending case is covered in the new suite. The backup version moves to 3.10.0.
- `sw-assets.test.cjs`: the upgrade scenario becomes 3.9.2 → 3.10.0.
- New `offline-friction.browser.cjs`: **24 scenarios** covering CR-01 to CR-03, CR-05 to CR-09, CX-01 with the CR-04 wording, FR-04, AG-14, R1–R7, Codex's additional R1 draft ownership edge cases, and Antigravity's account-switch in-flight flush isolation. These include controls for the in-window Blood alarm, the no-pending sign-out, and the prompt path when another window may own the draft. R1 uses real Web Locks with a live second window.
